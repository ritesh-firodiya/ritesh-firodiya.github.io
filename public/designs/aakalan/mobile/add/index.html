Add expense · one screen

Purpose: The most repeated action in the app. It has to be finishable in under ten seconds without a decision you didn't want to make.

"With" is a row, not a scroller. It used to be a horizontal strip of chips: Just me, then your groups, then your friends, then "New group". That works for three items and breaks for seven. It hid everything past the third behind a sideways swipe with no affordance that anything was there; it could not be searched; and it put four different kinds of thing — yourself, a person, a group, and an action that creates a group — on one axis as if they were the same kind of choice. With a flat, five groups and a dozen people it stops being a picker and becomes a carousel you scrub.

The row costs the same zero taps when the default is right, which is the case the scroller was built for. It arrives pre-set — to the group you opened Add from, or to whatever you used last — so the common path is unchanged. What changed is the uncommon path: instead of swiping past six chips looking for "Flat 402", you open a sheet that is searchable and sorted, and it works identically at nine hundred contacts.

The sheet sorts by kind, and puts Recent above everything. Just me first, because it is the answer that makes this an expense tracker. Then the three or four contexts you actually used this month, mixed — a person and a group are the same kind of answer to "who is this with", even though they are different rows everywhere else. Then all groups, then all people. "New group" is last, where a create action belongs.

One screen and one sheet each for the two questions. Who opens the With sheet; how it divides opens the split sheet. The split editor still opens only when the default is wrong, and the category is still guessed from what you typed rather than picked. Neither is a step in the common path.

"Just me" is the first option, and it is a real expense. This is what makes Aakalan an expense tracker and not only a Splitwise clone — same screen, same categories, same monthly total, not a group of one. When it is selected the split card simply isn't there.

Save is a sticky footer, not a header button. A footer sits outside the scroll container, so scrolling cannot hide it, and it is within reach of a thumb — which the top-right corner of a 6.7" phone is not.

The system keyboard, not a bespoke keypad. The description needs the system keyboard anyway, so a custom keypad would swap input methods mid-task. Description → amount → Save, on one keyboard.

Nothing is a required decision except two fields. Who, payer, split mode, category, date and receipt all arrive pre-answered on rows you may ignore. Product rule 3 — the per-head figure is printed, so nobody does arithmetic.

Paid-by wraps, it does not scroll either. Same reasoning, smaller list: a ten-person group's payer strip hid four people behind the edge of a sheet.
