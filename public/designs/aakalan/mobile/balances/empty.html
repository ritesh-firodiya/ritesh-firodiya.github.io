Balances · first run

Purpose: The screen that decides retention. Everything the app can do is currently zero, and the user has to be given exactly one thing to do next.

Nothing stands between signing up and this screen. Sign in, set your name, land here. A tour is a sequence of promises made before the user has seen a single feature.

Add an expense is the primary action, not Create a group. A solo expense works with zero friends and zero setup, so the app is useful on tap one. Group creation is the second button, for people who came here specifically to split something.

No contacts permission prompt. It is asked for at the moment someone actually adds a person to a group, with the reason on screen — not on day one for a feature they haven't reached.

The hero keeps its shape even at zero — the same compact card, the same neutral, so the screen the user learns on day one is the screen they use on day thirty. The two "₹0 / ₹0" sub-boxes went with it: printing zero three times is not reassurance, it is filler. And it keeps the colour rule too. It used to render the default indigo hero with a saffron orb, which made this the one frame in the set where the biggest number was painted a colour that meant nothing. ₹0 has no direction, so it takes the same neutral --settled treatment as the all-square state on Balances. Two screens showing ₹0 in two different colours is how a colour rule stops being a rule.

The three explainer bullets are gone. "On your own… With people… Offline works…" was a tour with the animation taken off, sitting under a heading that rejects tours. The one line worth keeping is the one that changes behaviour in the next ten seconds: you can add a bill in a basement restaurant. The other two are things the user is about to find out by doing them.
