Track what you spend. Split what you share.

23 screens · 2 tabs + Add · phone frame 390 × 844 · Riya as the signed-in user · ₹ INR

The product

Aakalan is two things that share one ledger. A personal expense tracker — log what you spend, see where it goes each month. A bill splitter — split anything with anyone, see who owes what, settle over UPI without leaving the app. An expense does not have to belong to a group: "Just me" is the first option on the add screen, and a personal expense uses the same categories and the same monthly totals as a shared one.

The wedge against Splitwise: the balance is the first thing you see, adding an expense takes three taps, settling happens in-app over UPI, and the free tier never caps the core loop. One Pro tier, priced below the incumbent, gating depth only.

The simplification pass

The set had grown to 24 screens and five tabs for a product with two halves. It is two tabs and one action now, each tab owning one half of the pitch. Every merge below was argued with a rule the set had already written down and was breaking somewhere else; the full reasoning is in each screen's sidebar rather than repeated here.

Friends → Balances. Home already refused a Groups tab because "a tab showing the same balance over the same list is the same screen twice". Friends was that exact screen, cut by person. It is a segmented control now, over one list sorted by size.

Insights → Spending. Insights refused a category-detail screen because it "would be a screen showing the same data again" — which is what it and Activity were to each other. The summary is the header and the rows are the body.

Account → the header avatar. It was always opened by tapping your own face. A settings screen visited twice a year held a tab while Insights, the whole tracker half, was a 20px icon.

Contacts browser → search. Two routes to one address book, one of them a list you scroll to find one name in nine hundred. What is left is the permission ask, the failures and the merge.

Eight horizontal chip scrollers → one picker row. A sideways strip works at three items and hides everything past the third, cannot be searched, and puts unlike things — yourself, a person, a group, and an action that creates a group — on one axis. Add, Add-with-one-person, Recurring and Settle all use the same row now: it names the current answer at rest, costs zero taps when the default is right, and opens one searchable sheet that works the same at nine hundred contacts.

Seventeen features removed: the expense comment thread, Google and Apple sign-in, the group Type picker, the duplicate Simplify toggle, weekly debt-reminder pushes, a notification switch labelled "can't be turned off", the "Half" settle amount, a UPI ID printed twice on one screen, the first-run explainer bullets, the separate contacts-browse destination — and now the "Add people" screen that replaced it, the per-contact "Add" button, the "Settle up" list screen, the UPI app chips, the settle-screen group breakdown, both all-square accordions, and the confirmation step on money you record receiving. Two undocumented shipped screens became one wireframed screen, and the group card became a group row.

Rules the design never breaks

1 · Green means someone owes you, rose means you owe. Reserved for money direction, including the balance hero — green, rose or neutral by direction, and all square is neutral, never green. The reservation covers every wheel: no avatar, group cover or category puck may be green or rose. Three were: av-riya was the literal --neg, so "you" wore a rose disc in every money row; av-meera and cat-home were the literal --pos. The one carve-out is a destructive action — Delete stays rose, because that convention is older and stronger than this rule.

2 · Every rupee figure is tabular-aligned (font-variant-numeric: tabular-nums) so columns of amounts line up.

3 · No screen makes the user do arithmetic. If a split is shown, the per-person figure is shown with it.

4 · Adding an expense is never paywalled, and neither is splitting, settling or exporting your own data.

5 · Edits and deletions are permanent, visible audit entries. An expense can be removed; the record that someone removed it cannot.

6 · A payment the PAYER claims requires the receiver's confirmation before any balance changes. Money you record receiving is true at once — you are the only one who can know it arrived, and the record reduces what the other person owes, so there is nobody it could cheat. This used to run "whichever side recorded it", which meant asking a debtor for permission to forgive their debt.

7 · Offline is the normal case. Writes queue locally and appear immediately as pending — never hidden until sync, or people add the same bill twice.

8 · A control that cannot be operated is a sentence. No disabled switches, no chips that set a number nobody owes, no second control over a behaviour that already has one.

Spending

the month, summarised then itemised

Two tabs, because the product is two things. Everything else is pushed: account, group detail, friend ledger, expense detail, settle, recurring, the paywall. A tab is for a place you return to; a push is for a place you go, do a thing and leave. Account is reached by tapping your own avatar, which is how it was always reached. There is no notifications screen and no pending-settlement banner. A claim someone made is a fact about that person, so it is an "Unconfirmed" flag on their row in Balances and the two buttons live on their ledger, one tap away — and a push notification deep-links straight to it. A banner reserved the top of the screen for a card that is absent most days and printed the same amount twice, once in itself and once in the row beneath it.

The folder tree and the route tree are the same shape. One folder per route area, index.html for that area's main screen, siblings named after their own route segment. The old tree was named after an information architecture that no longer exists — home/ held Balances, friends/ held a ledger and a contacts picker for a tab that had been deleted, and expense/ held the Add screen.

Every route now has a wireframe behind it, which was not true before: payments and numbers shipped with nothing describing either, and they are one screen now. Routes that go away: (tabs)/friends, (tabs)/activity, insights, (tabs)/account, payments, numbers. friend/[id] becomes person/[id] — the People cut is the only place the product still names them, and it does not say "friend".

Flagged, not cut

Multi-currency is the most expensive feature in the set per user served. It pays for a currency screen, a per-group currency, a money-bag type that cannot be summed, a two-currency hero state, and a currency selector on Spending — for an India-first app whose overwhelming case is rupees only. It ships, so removing it is not free, and nothing here removes it. It is recorded as the one place where the complexity and the audience do not match, so the next feature that looks like it gets asked the same question first.

Design system

Two files mirror each other: shared.css holds the tokens as CSS variables plus the components Tailwind can't express (phone frame, tab bar with the raised FAB, balance hero, money rows, split editor), and tailwind.config.js holds the same tokens as Tailwind scales — brand, saffron, pos, neg, ink, line, cat. When porting to React Native, translate those tokens into src/theme/tokens.ts rather than re-deriving colours by eye. Icons are Lucide, and every name used here exists in the app's installed lucide-react-native.
