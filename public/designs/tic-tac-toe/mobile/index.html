Tic Tac Toe — wireframes

Four routes, drawn in both themes. The app ships userInterfaceStyle: "automatic", so neither light nor dark is the default and a wireframe that drew only one would be drawing half the product.

Backfilled 2026-09-19, after the app shipped

The house rule is that a screen with no HTML file does not ship. This app shipped to Play without any, so these were drawn from the source afterwards rather than before — the one case in ~/git/products where the designs follow the code. Where a wireframe and the app disagree, the wireframe is the spec from here on; fix the screen, or change the wireframe first and say so.

The rules these drawings follow

  • Blue is X, rose is O, amber is the winning line. Nothing else may resolve to any of the three.
  • Tokens live in two files and cannot drift. shared.css defines them, tailwind.config.js exposes each as a utility written against var(--token). A token with no var has no utility.
  • Every value mirrors src/constants/theme.ts. That file is compiled and shipped; this is a drawing of it. If they disagree, theme.ts wins and the drawing is corrected in the same change.
  • Board geometry comes from src/constants/styles.ts — 6px gap, 12px padding, 2px border — not from eyeballing.
  • Markup is 100% Tailwind. No <style> blocks; inline style= only where a token must be interpolated into a gradient or a color-mix, which Tailwind cannot express against a CSS var.
